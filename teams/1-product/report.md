# گزارش تیم محصول و استراتژی — جواب‌سریع (JavabFast)

## خلاصه ۳ خطی
1. نیاز به جواب خودکار دایرکت محتمل است، ولی شدت نیاز، اندازه بازار و رقبای ایرانی هنوز اثبات نشده‌اند. سارا جست‌وجوی میدانی نکرد و همه موارد دانش عمومی یا تخمین است.
2. بزرگ‌ترین ریسک، دسترسی به API رسمی متا از ایران (تأیید اپ و بیزنس، تحریم، فیلترینگ) و مسیر پرداخت است. این باید قبل از هر ساخت جدی روشن شود.
3. MVP پیشنهادی امیر: اتصال اینستاگرام، پایگاه دانش فروشگاه، جواب فارسی فقط از همان دانش، «نمی‌دانم» به‌جای حدس، واگذاری به انسان و پنل ساده. برآورد ساخت P0 حدود ۴ تا ۶ هفته برای تیم ۲ تا ۴ نفره است (برآورد، نه قطعی).

## یافته‌های سارا (تحقیق بازار)
هیچ‌کدام از موارد زیر منبع ندارد و عددی در آن‌ها نیست.

1. **نیاز اصلی (اطمینان: متوسط):** بخش بزرگی از فروش فروشگاه‌های کوچک در دایرکت انجام می‌شود و سؤال‌های تکراری (قیمت، موجودی، ارسال، کارت‌به‌کارت) پرتکرارند. درصد فروشگاه‌هایی که حاضرند پول بدهند فقط تخمین است و با ۲۰ تا ۳۰ مصاحبه باید سنجیده شود.
2. **دسترسی به API متا (اطمینان: بالا درباره وجود مشکل، متوسط درباره جزئیات):**
   - API پیام‌رسانی اینستاگرام حساب حرفه‌ای، صفحه فیسبوک و اپ متا می‌خواهد و تأیید آن برای ایرانی‌ها دشوار یا مسدود است.
   - راه‌های غیررسمی با شرایط استفاده متا مغایرند و حساب مشتری را به خطر می‌اندازند.
3. **رقبای خارجی (اطمینان: متوسط):** ManyChat، Chatfuel و مشابه‌ها رقیب مستقیم نیستند، چون قیمتشان دلاری است، رابط فارسی ندارند و پرداخت دلاری برای فروشگاه کوچک دشوار است. میزان استفاده‌شان در ایران را نمی‌دانیم.
4. **رقبای ایرانی (اطمینان: پایین):** احتمالاً چند سرویس ایرانی و ابزارهای تلگرام، واتس‌اپ، بله و ایتا وجود دارند، ولی نام، قیمت و سهم بازارشان را نمی‌دانیم. باید ۵ تا ۱۰ سرویس را خودمان بررسی کنیم.
5. **پرداخت، هزینه مدل و کیفیت فارسی (اطمینان: متوسط):**
   - فروشگاه‌ها ریال و درگاه داخلی می‌خواهند، ولی APIهای مدل زبانی خارجی دلاری‌اند و دسترسی‌شان ممکن است محدود باشد.
   - مدل باید محاوره، فینگلیش و غلط املایی را تحمل کند.
   - جواب غلط درباره قیمت یا موجودی به اعتبار فروشگاه ضربه می‌زند. پیشنهاد سارا: جواب فقط از کاتالوگ فروشگاه و در شک واگذاری به انسان (پیشنهاد طراحی است، نه یافته بازار).

## یافته‌های امیر (فهرست MVP)
**فرض‌ها:** اتصال از مسیر API رسمی متا؛ پنجره ۲۴ ساعته متا یعنی ربات فقط به پیام ورودی جواب می‌دهد؛ تا اندازه‌گیری روی مشتری واقعی هیچ وعده عددی (دقت، فروش) نمی‌دهیم.

**P0 — ضروری:**
1. اتصال حساب اینستاگرام با OAuth متا.
2. دریافت پیام ورودی و ارسال پاسخ خودکار.
3. پایگاه دانش ساده (محصول، قیمت، ساعت کاری، آدرس، ارسال، پرداخت).
4. جواب هوش مصنوعی به فارسی (از جمله محاوره) فقط بر پایه همان دانش.
5. «نمی‌دانم» به‌جای حدس‌زدن، با جمله ثابت که فروشنده به‌زودی جواب می‌دهد.
6. واگذاری به انسان (کلید در هر گفتگو؛ ربات خودش شکایت و درخواست «با آدم صحبت کنم» را علامت می‌زند).
7. اطلاع‌رسانی به فروشنده هنگام نیاز به دخالت (پیامک یا ایمیل).
8. صفحه گفتگوها برای دیدن و دخالت.
9. کلید خاموش/روشن کل ربات.
10. لاگ همه پیام‌ها و پاسخ‌ها.
11. پنل وب فارسی، راست‌به‌چپ و موبایل‌پسند.
12. ورود با شماره موبایل و کد یکبارمصرف.
13. حریم خصوصی حداقلی (جداسازی داده فروشگاه‌ها، امکان حذف داده).

**P1 — مهم:** قالب راه‌اندازی بر اساس نوع کسب‌وکار؛ محیط تست داخل پنل؛ ساعت فعالیت ربات؛ پاسخ ثابت به صوت و عکس؛ برچسب‌گذاری گفتگوها؛ گزارش هفتگی ساده از لاگ؛ پیشنهاد افزودن به دانش از پرسش‌های بی‌پاسخ؛ پرداخت اشتراک (ابتدا دستی یا فاکتور)؛ سقف پیام ماهانه برای کنترل هزینه.

**P2 — بعداً:** اتصال به موجودی/سبد؛ ثبت سفارش و آدرس؛ پرداخت درون گفتگو؛ کامنت و استوری؛ فهم تصویر محصول؛ پیگیری فعال؛ چندکاربره؛ اپ موبایل و تلگرام/واتساپ؛ تحلیل پیشرفته.

**عمداً نمی‌سازیم:** وعده عددی؛ ربات سفارش‌گیر و پرداخت‌گیر کامل؛ آموزش مدل اختصاصی؛ پنل پیچیده؛ اتصال به CRM/حسابداری/انبار؛ تشخیص صدا و تصویر؛ پیام تبلیغاتی فعال؛ دور زدن API رسمی (اسکرپینگ، لاگین با رمز)؛ چندزبانه.

**ریسک‌های زودرس:** درخواست تأیید اپ متا در هفته اول؛ تست کیفیت فارسی با چند ده پیام واقعی؛ روشن‌کردن مسیر عملی دسترسی و پرداخت در ایران؛ اندازه‌گیری هزینه هر گفتگو قبل از قیمت‌گذاری.

## تصمیم‌ها
1. **هیچ ادعای بازار** (اندازه بازار، سهم و قیمت رقبا، درصد صرفه‌جویی یا فروش) نوشته نشود تا با منبع تأیید شود.
2. **جواب فقط از دانش فروشنده** و در شک واگذاری به انسان. حدس درباره قیمت یا موجودی ممنوع است.
3. **اتوماسیون غیررسمی محصول نمی‌شود.** فقط API رسمی یا مسیرهای جایگزین مجاز است.
4. **دامنه MVP همان P0 است.** P1 فقط اگر زمان بماند و P2 بعد از یادگیری از مشتری واقعی.
5. **ساخت جدی شروع نمی‌شود** تا امکان‌سنجی API و مصاحبه‌ها انجام شود.
6. باز است: حالت پیش‌نویس (فروشنده تأیید کند) یا جواب کاملاً خودکار از روز اول. امیر خودکار با واگذاری را پیشنهاد داده؛ تا آزمون کیفیت فارسی انجام نشده، حالت پیش‌نویس در هفته‌های اول محتاطانه‌تر است. تصمیم نهایی بعد از آزمون.

## قدم بعدی
1. **امکان‌سنجی API متا از ایران** (فنی و حقوقی) و تعیین مسیر جایگزین اگر ممکن نبود. اولویت اول؛ درخواست تأیید اپ در صورت ممکن بودن همان هفته اول.
2. **بررسی ۵ تا ۱۰ رقیب ایرانی و خارجی** با منبع، قیمت و قابلیت.
3. **۲۰ تا ۳۰ مصاحبه** با فروشندگان اینستاگرامی و جمع‌آوری نمونه گفتگوهای واقعی (با رضایت) برای شمردن سؤال‌های تکراری و سنجش آمادگی پرداخت.
4. **آزمون کیفیت فارسی** با چند ده پیام محاوره‌ای و بررسی دستی جواب‌ها.
5. **سنجش مسیر پرداخت و هزینه** مدل زبانی به ازای هر گفتگو.
6. بعد از ۱ تا ۵: تصمیم می‌گیریم MVP روی API رسمی ساخته شود یا نسخه مستقل از اینستاگرام (مثل دستیار پیش‌نویس یا تلگرام).
